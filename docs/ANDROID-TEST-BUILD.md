# Android standalone APK with GitHub Actions

The workflow `.github/workflows/android-test-apk.yml` creates an optimized standalone release APK that can be installed directly on an ARM64 Android device without Metro. It does not use EAS Build or require an Android release keystore.

## GitHub configuration

Open **Settings → Secrets and variables → Actions** in the repository.

Create this repository variable:

| Variable | Value |
| --- | --- |
| `EXPO_PUBLIC_API_URL` | The API URL reachable from the test device, such as `https://api.example.com`. |

Create this repository variable (the workflow also accepts a secret with the same name):

| Variable | Value |
| --- | --- |
| `ANDROID_GOOGLE_SERVICES_JSON_BASE64` | Base64 of Firebase `google-services.json` for package `com.igen.connect`. |

Convert the Firebase file to Base64 in PowerShell:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("google-services.json")) | Set-Clipboard
```

Paste the clipboard value into `ANDROID_GOOGLE_SERVICES_JSON_BASE64`. The workflow reconstructs the file only on the temporary runner.

## Build and install

The workflow runs automatically only when changes are pushed or merged into `production`. To run it manually, open **Actions → Android standalone APK → Run workflow**.

After it succeeds:

1. Open the workflow run.
2. Download `igen-connect-standalone-arm64-<run-number>` under **Artifacts**.
3. Extract the downloaded ZIP.
4. Copy `app-release.apk` to the Android device and install it.

Android may require enabling **Install unknown apps** for the browser or file manager used to open the APK.

The APK embeds its JavaScript bundle, enables R8 minification and resource shrinking, compresses native libraries, and includes only the `arm64-v8a` ABI to reduce download size. It therefore does not support 32-bit ARM or x86 devices/emulators.

The release variant still uses Android's standard debug signing key generated by Gradle on the runner. It is intended only for internal testing and cannot be uploaded as a production release to Google Play. A Play Store build needs a persistent release keystore and should normally be distributed as an Android App Bundle (`.aab`).
